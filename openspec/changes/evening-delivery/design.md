## Context

See proposal.md and issue #214. Production at def1815 uses a shared gate with three stories/two repairs and an evening process with thirty discovery turns, five turns per repair and a twenty-minute timeout. Cron runs once at 18:00 Europe/Berlin. State currently preserves review logs but cannot resume work. The morning worker imports shared transport/gate modules, so evening-only policy must be explicit.

## Goals / Non-Goals

Goals: durable progress, unlimited total repair opportunities, finite activations, independent full review, observable recovery. Non-goals: bypassing checks, promising availability of external services, changing morning scheduling or editorial behavior (only final publication coordination is shared), sending operational notifications to Telegram, or claiming exactly-once delivery without transport reconciliation.

## Decisions

### Edition journal and policy

Create versioned per-edition state under the existing private evening state directory. Atomically checkpoint before and after every external operation, including the latest draft, primary/supporting evidence and fetch times, cover identity, all findings, abandoned-source identifiers, counters, last error, nextAttemptAt and transport outcome. Store review history as append-only records; pass bounded recent history plus the full set of outstanding findings to avoid unbounded model context. Never persist secrets. Use temp-file write, file fsync, rename and directory fsync; reject corrupt/unknown state versions without erasing them.

Phases: discovering -> drafting -> reviewing -> repairing -> ready -> sending -> published. Temporary failures retain phase with retry metadata; invalid configuration/state remains blocked; an uncertain send becomes delivery-unknown. A repair verdict increments a durable counter with no terminal count. Replacement needs an explicit freshness/grounding/source-validation reason, not elapsed turns. The shared gate keeps its current default morning policy and gains an explicit persistent evening policy; restored approval objects never authorize sending. Every resumed candidate is fully reviewed again, and any mutation invalidates approval.

Alternative: an infinite process or merely raising the turn limit. Rejected because a crash still loses all progress and repeated ineffective searches consume resources without delivery.

### Work limits and scheduling

Replace only the tagged evening cron entry with a five-minute scheduler tick using the existing exclusive flock. Create editions due at 18:00 Europe/Berlin, never earlier; initialize a durable activation date at deployment and enqueue missing due dates from that date on recovery. Preserve original edition weekday/date while supplying current date for honest delayed copy. Schedule eligible editions fairly by least recent activation, breaking ties by oldest due date, at most one confirmed send per tick; an explicitly blocked/delivery-unknown edition is excluded from runnable work so it cannot starve newer editions. Successful markers suppress work across restarts and DST transitions. No pre-deployment backfill unless explicitly requested.

Each activation permits at most five minutes and twenty model calls total (writer and editor), with a shared ceiling of forty external operations including model, discovery, tool, feed, article, cover and transport requests; redirects/retries each consume an operation. Model calls have a sixty-second timeout and other network operations a fifteen-second timeout, clipped to the activation deadline. Reserve two model calls, four external operations and ninety seconds for full review and final delivery; checkpoint/yield before starting that phase if this capacity is unavailable. Checkpoint before every external call. Reserve capacity for review; after source verification draft immediately. Writer work chunks are at most five calls before checkpoint/yield. Editorial repairs have no lifetime ceiling. Routine unfinished work retries at the next five-minute tick. Dependency failures use persisted exponential delays of 5, 10, 20, 40, then 60 minutes; honor longer Retry-After values. Read-only checks for blocked auth/config failures run hourly. Local status marks an edition overdue thirty minutes after due time. No new operational messages are sent to people/channels.

An unsent ready payload crossing activations loses its ephemeral approval and must be reviewed against fresh confirmed history. Re-fetch sources and cover before resumed review; preserve the draft when dependencies are temporarily unavailable. On midnight crossing, remove or update stale relative dates and validate time-sensitive numbers against current source evidence. Edition identity and actual publication timestamp remain distinct. Persist cancelled editions only through an explicit operator action with reason.

### Discovery recovery

Persist queries, visited sources and unusable URLs. After three search calls without a usable fetched candidate, switch away from search to configured primary-source RSS/Atom feeds and a persisted reserve queue of previously fetched unused candidates. Ship a documented nonempty feed list, selected and verified during implementation; test selection independent of one search provider. Fetch original articles and original source covers anew, filter against confirmed history and the edition category, and run normal editorial review. Feed/reserve exhaustion checkpoints progress and retries; never turn discovery failure into fabricated content or a text-only fallback. Cached candidates are not pre-approved posts. Prune candidate bodies to bounded excerpts while preserving URLs and evidence needed by the editor.

### Sending and observability

Keep existing channel/account identity checks and caption/cover constraints. Bind send intent and ephemeral authorization to caption, target channel and validated cover-byte hash; send those validated media bytes rather than refetching a mutable URL during delivery. A changed caption, target or media invalidates authorization. Under the evening lock persist sending intent with exact payload hash, edition and start time before the network request. Persist a confirmed Telegram message ID before archive/marker updates; replay local finalization after a crash without resending. If intent exists without durable confirmation, block as delivery-unknown. A documented reconcile command accepts a verified existing message ID or explicit operator-confirmed non-delivery, records evidence and changes state under the slot and shared publication locks. Existing-message reconciliation must verify the exact target channel, message ID, caption and media against the stored send intent; a wrong-channel or mismatched-payload ID cannot close an edition. When history cannot be read through the integration, require recorded operator attestation identifying the channel/message link and matching caption/media, with timestamp and evidence reference; never label this automatic verification. Non-delivery reconciliation requires recorded explicit operator evidence from channel inspection; never infer non-delivery from elapsed time or a missing marker. Known API rejection is classified separately from timeouts/unknown outcome. Before selecting runnable work, idempotently finalize every confirmed-but-unfinalized journal into archives/history and markers keyed by edition/message ID. If finalization fails, block new publication until confirmed history is complete. Both morning and evening final delivery paths use one short shared publication lock, acquired after each slot lock; no reverse lock ordering. Research and full model review run outside this shared lock. Record the reviewed history fingerprint; inside the lock reload history, and if it changed, release the lock and re-review before sending. Hold the shared lock through send-intent persistence, delivery and local finalization. Morning retains its schedule, prompts and editorial limits; this coordination is its only behavior change. Recovery checks for unfinished confirmed journals apply before either slot sends.

Add an offline status command over the journal and timestamped transitions. A non-publishing mode uses isolated state, bypasses live send entirely and never changes live journals, schedules, archive or markers. No automatic public smoke tests.

## Risks / Trade-offs

- Endless subjective disagreement -> no silent cancellation, bounded rates, status exposes findings and age; no assertion that all providers/gates must eventually succeed.
- Long outages create backlog -> persistent dated editions, fair rotation among runnable editions, one send per tick; explicit cancellation remains possible.
- Ambiguous delivery -> deliberate reconciliation block; eventual automatic delivery cannot be guaranteed without a reliable transport idempotency primitive.
- Shared gate regression -> explicit evening policy and unchanged morning regression tests.
- Disk failure or invalid schema -> visible blocked state; no unchecked send or silent state reset.

## Migration Plan

Five independent spec reviews, owner approval and passing spec CI precede implementation. Implement at existing public gate and real worker subprocess seams, with Rust runner tests first; cover more than ten repairs, restarts, exhausted discovery, dependency recovery, DST/midnight, duplicate suppression and uncertain sends. Validate controlled fixtures first, then non-publishing installed-model checks with finite budgets.

After implementation review and green CI, install coherent bundle under existing locks, initialize activation date and change only the evening tagged cron line. Preserve cron, release links and journals in rollback backup; verify installed hashes and first scheduled outcomes. Rollback disables the new evening tick and preserves journals/send intents; do not reactivate the legacy evening sender until all open/unknown editions are reconciled, because it cannot read the new journal. Morning continues unchanged.
